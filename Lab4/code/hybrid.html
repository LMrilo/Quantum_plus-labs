Variational Quantum Algorithms

Hybrid Classical-Quantum Computing — VQE & QAOA

75 min Prerequisites: Labs 1–2 (gates, CNOT, two-qubit states) NISQ-Era Focus Bridge to Lab 4 Finance

Today's quantum computers cannot run the deep circuits required by Shor or Grover on large inputs. The practical solution is hybrid algorithms for NISQ (Noisy Intermediate-Scale Quantum) processors, such as the Variational Quantum Eigensolver (VQE) and the Quantum Approximate Optimization Algorithm (QAOA): short parametric quantum circuits evaluated repeatedly, guided by a classical optimizer. This lab builds the full technical foundation for the finance application in Lab 4 Finance.

 The NISQ Constraint

Without error mitigation, today's best quantum processors (QPUs) keep a usable signal for a few hundred two-qubit gates before noise dominates; with error mitigation, IBM has run circuits of about 3,000 (2023) to 5,000 (2024) two-qubit gates. VQE and QAOA are designed around this limit: the quantum circuit is kept shallow while the classical optimizer does the heavy lifting of navigating the parameter space.

Before Part A: the variational loop

Every algorithm in this lab runs the same loop. A short quantum circuit with adjustable rotation angles $\theta$ prepares a state; a classical program reads the measurement results and adjusts the angles:

  1. choose angles $\theta$;
  2. run the circuit and measure it many times (each run is one shot);
  3. average the results into one number, the cost $C(\theta)$;
  4. a classical optimizer proposes new angles that should lower $C$. Repeat until $C$ stops decreasing.
  • $Z$ as a score. From Lab 1, $Z=\mathrm{diag}(1,-1)$: it gives the value $+1$ to $|0\rangle$ and $-1$ to $|1\rangle$. $Z_i$ means $Z$ acting on qubit $i$, and $Z_0Z_1$ multiplies the two values: $+1$ if the two bits are equal, $-1$ if they differ.
  • Hamiltonian $H$ (the energy function). A sum of such terms that gives every bit string a number, its energy. Part B uses $H=Z_0Z_1+0.5\,Z_0$: $|00\rangle\to 1.5$, $|01\rangle\to -0.5$, $|10\rangle\to -1.5$, $|11\rangle\to 0.5$ (first symbol = qubit 0). A problem is encoded so that its best answer is the bit string of lowest energy, the ground state, with energy $E_0$ (here $-1.5$, at $|10\rangle$). Because these Hamiltonians contain only $Z$'s, each bit string has one definite energy (in matrix language, it is an eigenvector of $H$ and the energy is its eigenvalue).
  • Expectation value $\langle H\rangle$ (the cost). A superposition has no single energy: each shot returns one bit string $x$, with probability $P(x)$, and its energy $E(x)$. The average over many shots is $\langle H\rangle=\sum_x P(x)\,E(x)$. This is the cost $C(\theta)$. For one qubit, $\langle Z\rangle = P(0)-P(1)$.
  • Why minimising works. An average can never be lower than the smallest value it averages, so $C(\theta)\ge E_0$ for every $\theta$, with equality only when all the probability sits on the ground state (the variational principle). Pushing $C$ down pushes the state toward the answer.
  • Ansatz $U(\theta)$. German for "educated guess": a fixed circuit layout whose rotation angles are the adjustable parameters. The rotation used here is $R_y(\theta)$, which turns $|0\rangle$ into $\cos\tfrac{\theta}{2}|0\rangle+\sin\tfrac{\theta}{2}|1\rangle$; so $R_y(0)$ does nothing and $R_y(\pi)|0\rangle=|1\rangle$.
  • Classical optimizer. Ordinary numerical software, nothing quantum. Gradient-based optimizers follow the slope downhill and need the gradient, which Part A shows how to obtain from the quantum computer (the Part B widget works this way). Gradient-free optimizers such as COBYLA (Constrained Optimization BY Linear Approximations, used in Part E and the notebook) only compare cost values.

On real hardware each $C(\theta)$ is estimated from a finite number of shots and carries noise; the widgets on this page use exact values. Optional, more formal derivations: Lab 4 Notes (PDF), Parts A–C.

Part A: The Parameter-Shift Rule

Start with the smallest case: one qubit and one angle. Apply $R_y(\theta)$ to $|0\rangle$ and measure. The state is $\cos\tfrac{\theta}{2}|0\rangle+\sin\tfrac{\theta}{2}|1\rangle$, so $P(0)=\cos^2\tfrac{\theta}{2}$, $P(1)=\sin^2\tfrac{\theta}{2}$, and the average of $Z$ is $f(\theta)=\langle Z\rangle=P(0)-P(1)=\cos\theta$. We write it $\langle Z\rangle_{R_y(\theta)}$. A gradient-based optimizer needs the slope of this curve, the derivative $\partial_\theta f$ (here $-\sin\theta$). But a quantum computer returns only values of $f$, never its formula. The trick is to evaluate $f$ at two shifted angles: $\tfrac12\left[\cos(\theta+\tfrac{\pi}{2})-\cos(\theta-\tfrac{\pi}{2})\right]=\tfrac12\left[-\sin\theta-\sin\theta\right]=-\sin\theta$. That is the exact slope, not an approximation. At $\theta=0.5$: $f(2.071)=-0.479$, $f(-1.071)=+0.479$, and half their difference is $-0.479=-\sin 0.5$.

The same shift works for every rotation of the form $G(\theta)=e^{-i\theta P/2}$, where $P$ is a Pauli operator ($X$, $Y$, $Z$ or a product such as $Z_0Z_1$). The exponential is shorthand for $\cos\tfrac{\theta}{2}\,I-i\sin\tfrac{\theta}{2}\,P$; with $P=Y$ it is exactly $R_y(\theta)$. For such a gate the measured average always has the form $a+b\cos\theta+c\sin\theta$ ($a,b,c$ depend on the rest of the circuit, not on $\theta$), and for every such function:

$\partial_\theta f = \tfrac{1}{2}\left[f(\theta + \pi/2) - f(\theta - \pi/2)\right]$

This holds when $\theta$ enters a single gate. If one angle drives several gates (as $\gamma$ does in Part C), apply the rule to each gate and add the results.

Part B: VQE Cost Landscape

Hamiltonian (2-Qubit Ising Model: an energy built from $Z$ products): $H = Z_0Z_1 + 0.5\,Z_0$. Ansatz: $\mathrm{CX}_{01}(R_y(\theta_0)\otimes R_y(\theta_1))|00\rangle$. The heatmap shows $C(\theta_0, \theta_1)$ — the optimizer must find the global minimum at $(\pi, \pi)$ with energy $E_0 = -1.5$.

Reading the landscape. $Z_0Z_1$ is $+1$ when the two qubits agree and $-1$ when they differ. $0.5\,Z_0$ adds $+0.5$ if qubit 0 is $|0\rangle$ and $-0.5$ if it is $|1\rangle$. So the four bit strings have energies $|00\rangle{:}\ 1.5$, $|01\rangle{:}\ {-0.5}$, $|10\rangle{:}\ {-1.5}$, $|11\rangle{:}\ 0.5$, and the ground state is $|10\rangle$ with $E_0=-1.5$. The ansatz reaches it at $(\pi,\pi)$: $R_y(\pi)$ turns both qubits into $|1\rangle$, then the CX (control qubit 0) flips qubit 1 back, $|11\rangle\to|10\rangle$. For general angles, working out the four probabilities gives $C(\theta_0,\theta_1)=\langle H\rangle=\cos\theta_1+0.5\cos\theta_0$, the formula the heatmap colours. Its lowest value is $-1-0.5=-1.5=E_0$, and no point of the map goes lower.

What the optimizer does here. At each step it measures the two slopes $\partial C/\partial\theta_0$ and $\partial C/\partial\theta_1$ with the parameter-shift rule of Part A (four cost evaluations) and takes a small step downhill. Click near a red corner and watch the path bend toward the crosshair at $(\pi,\pi)$.

Part C: QAOA for MaxCut — 4-Node Cycle

Graph $C_4$: nodes $\{0,1,2,3\}$, edges $\{(0,1),(1,2),(2,3),(3,0)\}$. Optimal cut = 4 edges (partition $\{0,2\}$ vs $\{1,3\}$). Explore how the number of QAOA layers $p$ changes the approximation ratio and how much probability lands on the two optimal bitstrings $|0101\rangle$ and $|1010\rangle$.

The problem. Split the four nodes into two groups. An edge is cut if its two ends land in different groups; MaxCut asks for the split that cuts the most edges. Write a split as a bit string, one bit per node, read left to right as nodes 0, 1, 2, 3 (0 = one group, 1 = the other). $|0101\rangle$ puts $\{0,2\}$ against $\{1,3\}$ and cuts all 4 edges, the best possible; $|0000\rangle$ cuts none.

From graph to Hamiltonian — derivation

The MaxCut objective counts the number of edges $(i,j)$ where nodes $i$ and $j$ are in different partitions. Assign $x_i \in \{0,1\}$ to each node. Edge $(i,j)$ is cut iff $x_i \neq x_j$, i.e., $x_i + x_j - 2x_ix_j = 1$. So:

$$\text{MaxCut}(x) = \sum_{(i,j)\in E} (x_i + x_j - 2x_ix_j)$$

Substituting $x_k = \frac{1-Z_k}{2}$ (so $x_k=0 \leftrightarrow Z_k=+1$, $x_k=1 \leftrightarrow Z_k=-1$):

$$x_i + x_j - 2x_ix_j = \frac{1-Z_i}{2} + \frac{1-Z_j}{2} - 2\cdot\frac{1-Z_i}{2}\cdot\frac{1-Z_j}{2} = 1 - \frac{1+Z_iZ_j}{2} = \frac{1-Z_iZ_j}{2}$$

Therefore the cost Hamiltonian is:

$$H_C = \sum_{(i,j)\in E} \frac{I - Z_iZ_j}{2}$$

Intuition: $Z_iZ_j$ has eigenvalue $+1$ when both qubits are equal (not cut), and $-1$ when they differ (cut). So $\frac{I-Z_iZ_j}{2}$ equals 1 for a cut edge and 0 otherwise — exactly what we want.

The mixer Hamiltonian $H_B = \sum_i X_i$ creates transitions between bit strings. The $X$ gate flips $|0\rangle \leftrightarrow |1\rangle$, so $e^{-i\beta H_B}$ allows the optimizer to explore different node assignments — without it, the algorithm would stay stuck in its initial state.

The QAOA recipe (Quantum Approximate Optimization Algorithm). (1) Start from H on every qubit (Lab 1): all 16 splits equally likely. (2) Cost layer: on each edge, a phase whose sign depends on whether that edge is cut, with strength $\gamma$. (3) Mixer: $R_x(2\beta)$ on every qubit, a rotation that mixes $|0\rangle$ and $|1\rangle$ (this is the gate written $e^{-i\beta X}$; applied to all qubits it is $e^{-i\beta H_B}$). (4) Repeat steps 2–3 $p$ times, each layer with its own $(\gamma_k,\beta_k)$: $2p$ angles in all. (5) Measure: each shot returns one split. A classical optimizer tunes the $2p$ angles to maximise the average number of cut edges. The approximation ratio is that average divided by the best possible cut (4 here); 1 means every shot returns an optimal split.

Convention: the circuit applies $e^{-i\gamma Z_iZ_j}$ on each edge (CNOT, $R_z(2\gamma)$, CNOT). Since $H_C=\sum(I-Z_iZ_j)/2$, this equals $e^{-i\gamma' H_C}$ with $\gamma'=-2\gamma$ times an overall phase factor that changes no probability: the same family of circuits with a rescaled angle.

 The Portfolio Optimization QUBO

In Lab 4 Finance you will minimise a Quadratic Unconstrained Binary Optimization (QUBO) objective over $n$ binary asset variables $x \in \{0,1\}^n$:

$\min_{x \in \{0,1\}^n}\; x^T Q\, x \quad\text{where}\quad Q_{ij} = \lambda\,\Sigma_{ij} - \mu_i\,\delta_{ij}$

($\Sigma_{ij}$: return covariance; $\mu_i$: expected return; $\lambda$: risk-aversion parameter.)

Substituting $x_i = (1 - Z_i)/2$, the objective becomes the cost Hamiltonian of a QAOA circuit:

$H_\text{portfolio} = \sum_{i,j} Q_{ij}\, \dfrac{(I - Z_i)(I - Z_j)}{4} \;+\; \underbrace{\lambda_\text{pen}\!\left(\sum_i \frac{I-Z_i}{2} - K\right)^{\!2}}_\text{budget constraint penalty}$

Connection to this lab:

  • The QAOA circuit structure ($e^{-i\gamma H_C}$, $e^{-i\beta H_B}$) is identical to the MaxCut circuit of Part C (code in Part E).
  • The $ZZ$ rotation $e^{-i\gamma Z_iZ_j}$ is implemented with the same CNOT–$R_z$–CNOT decomposition.
  • The classical optimizer is unchanged; only $H_C$ is different. COBYLA (used in Part E) is gradient-free: it only compares cost values. A gradient-based optimizer would take its slopes from the parameter-shift rule of Part A. Because each $\gamma_k$ drives one gate per edge, the rule is applied to every such gate and the results added.

Part E: Qiskit Python Implementation

Exercises 1–3: PSR (parameter-shift rule), VQE, QAOA Open Colab Notebook

This script runs the QAOA of Part C on a simulator for $p=1,2,3$. build_qaoa builds the circuit (H on every qubit, then $p$ cost-and-mixer layers). maxcut_hamiltonian writes $H_C$, the number of cut edges, as a sum of Pauli terms. The EstimatorV2 returns the exact average $\langle H_C\rangle$ for a given set of angles, and COBYLA, a classical optimizer that needs no gradient, tunes the $2p$ angles starting from 0.5. The Colab notebook contains this exercise (Exercise 3) together with the parameter-shift check (Exercise 1) and the VQE of Part B (Exercise 2).

Expected output: p=1 MaxCut≈3.000/4 ratio≈0.750, then ratio≈1.000 for $p=2$ and $p=3$, the same numbers as the simulator above.

from qiskit import QuantumCircuit
from qiskit.circuit import Parameter, ParameterVector
from qiskit.quantum_info import SparsePauliOp
from qiskit_aer.primitives import EstimatorV2
from scipy.optimize import minimize

# ── QAOA circuit for MaxCut ─────────────────────────────────────────────────
def build_qaoa(n, edges, p):
    g = ParameterVector('γ', p)
    b = ParameterVector('β', p)
    qc = QuantumCircuit(n)
    qc.h(range(n))
    for k in range(p):
        for (u, v) in edges:          # cost unitary e^{-iγ ZZ}
            qc.cx(u, v)
            qc.rz(2 * g[k], v)
            qc.cx(u, v)
        qc.rx(2 * b[k], range(n))     # mixer e^{-iβ X}
    return qc, list(g) + list(b)

# ── MaxCut Hamiltonian H_C = Σ (I - ZiZj) / 2 ─────────────────────────────
def maxcut_hamiltonian(n, edges):
    terms = []
    for (u, v) in edges:
        zz = ['I'] * n
        zz[u] = 'Z'; zz[v] = 'Z'
        terms += [(''.join(reversed(zz)), -0.5),
                  ('I' * n,                0.5)]
    return SparsePauliOp.from_list(terms).simplify()

# ── Run QAOA ────────────────────────────────────────────────────────────────
edges = [(0,1), (1,2), (2,3), (3,0)]   # 4-cycle C4
for p in [1, 2, 3]:
    qc, params = build_qaoa(4, edges, p)
    H = maxcut_hamiltonian(4, edges)
    est = EstimatorV2()

    def cost(x):
        job = est.run([(qc, H, x)])
        return -job.result()[0].data.evs   # negate: maximise cut

    x0  = [0.5] * (2*p)
    res = minimize(cost, x0, method='COBYLA')
    print(f"p={p}  MaxCut≈{-res.fun:.3f}/4  ratio≈{-res.fun/4:.3f}")
